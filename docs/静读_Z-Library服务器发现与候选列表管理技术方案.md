# 静读 Android：Z-Library 服务器发现与候选列表管理技术方案

版本：1.0｜性质：在线书库统一化方案的补充需求｜实施对象：Codex

## 1. 目标与范围

支持自动检测与手动指定两种模式；用户可以直接在 UI 中维护自动检测的候选地址，无需重新打包 APK。保留内置默认列表、JSON 导入导出、配置回滚和最近可用地址缓存。第一版不引入远程配置中心、自动订阅或动态脚本。自动发现仅指检测已知候选地址，不保证发现全新域名。

参考仓库：https://github.com/ZlibraryKO/zlibrary.koplugin 。实施前核实固定 commit 的实际发现机制及许可证，记录差异；本文是静读拟实施设计，不声称与原插件完全一致。仅使用合法授权资源测试。

## 2. 页面与交互

入口：云端 → Z-Library → 书源设置 → 服务器配置。沿用现有 UI 框架、主题和导航，不增加底部导航项。

```text
┌──────────────────────────────────┐
│ ‹ 服务器配置                     │
│ ○ 手动指定   ● 自动检测          │
│ 当前服务器：server-a.example.com │
│ 最近检测：2026-11-24 16:20       │
│                                  │
│ 候选服务器（2/3 已启用）   + 添加│
│ ┌──────────────────────────────┐ │
│ │ 1. server-a.example.com   ON │ │
│ │ 可用 · 230ms · 当前使用      │ │
│ │ 检测   编辑   下移   删除    │ │
│ ├──────────────────────────────┤ │
│ │ 2. server-b.example.com   ON │ │
│ │ 连接超时                     │ │
│ │ 检测   编辑   上移   删除    │ │
│ ├──────────────────────────────┤ │
│ │ 3. server-c.example.com  OFF │ │
│ │ 已禁用                       │ │
│ └──────────────────────────────┘ │
│ [检测全部]    [重新选择服务器]   │
│ [批量导入]    [导出列表]         │
│ [恢复内置默认列表]               │
└──────────────────────────────────┘
```

示例域名、状态、时间均为演示数据。新增/编辑弹窗包含地址输入、启用开关、取消、保存；保存后标记未检测。删除、恢复默认、替换导入需确认。排序支持上下移动，可选拖拽。单独检测仅更新该项状态，不自动改变当前地址；检测全部显示逐项结果，重新选择才主动切换。禁用项不参与检测全部。检测期间允许取消，防止重复提交。

手动模式只显示固定地址、保存、测试连接及状态；失败不自动切换。切换模式保留另一模式的配置。空列表或全部禁用时显示添加地址、恢复默认入口，不循环重试。

## 3. 配置与数据模型

建议复用现有配置仓库，JSON 文件持久化，不新增数据库表。用户配置、内置默认配置、运行状态分离。以下地址均为占位符。

```json
{
  "schemaVersion": 1,
  "configVersion": "1.0.0",
  "server": {
    "mode": "auto",
    "manualBaseUrl": "",
    "candidates": [
      {"id": "a", "baseUrl": "https://server-a.example.com", "enabled": true, "priority": 1},
      {"id": "b", "baseUrl": "https://server-b.example.com", "enabled": true, "priority": 2}
    ]
  },
  "discovery": {"timeoutMs": 5000, "cacheTtlSeconds": 86400, "maxConcurrentProbes": 3}
}
```

```kotlin
enum class ServerMode { AUTO, MANUAL }
data class ServerCandidate(val id: String, val baseUrl: String, val enabled: Boolean, val priority: Int)
enum class ProbeStatus { UNTESTED, CHECKING, AVAILABLE, TIMEOUT, NETWORK_ERROR, TLS_ERROR, API_INCOMPATIBLE, CANCELLED }
data class ProbeResult(val candidateId: String, val status: ProbeStatus, val latencyMs: Long?, val checkedAt: Long)
data class DiscoveryState(val lastAvailableBaseUrl: String?, val lastCheckedAt: Long?, val configRevision: Long)
```

运行状态不写入用户导出配置。优先级数字越小越优先，排序后重新编号。配置修改采用原子写入，失败保留旧配置。升级时迁移 schema，禁止用新版内置列表覆盖用户列表。旧字符串数组可迁移为启用的对象数组。保留上一份有效配置以便回滚。

## 4. 地址管理与导入导出

使用成熟 URL 解析器校验 HTTPS 地址；拒绝 userinfo、查询参数、fragment、非法端口及不符合既定 API 基址格式的路径。规范化主机大小写、默认端口和尾部斜杠后判重，不随意改写路径大小写。设置列表长度及导入文件大小上限（建议 50 项、256 KiB）。

支持 JSON 和每行一个地址的纯文本导入，先解析、校验、预览新增/重复/无效项，再由用户确认合并或替换。合并保留现有项设置，新增项追加；替换需二次确认。无效配置不得覆盖当前配置。导出只包含地址、启用状态、顺序及版本，不包含认证信息。恢复默认只恢复服务器列表，不清除账号或其他书源设置。

## 5. 检测与选择策略

- 自动模式优先复用仍启用、仍在当前配置中且缓存未过期的最近可用地址；缓存 TTL 默认 24 小时。
- 首次使用、缓存过期、当前地址持续连接异常、用户主动重新选择或相关配置变更时重新评估。
- 按优先级分批检测，最大并发 3，单次探测总超时 5 秒；选择优先级最高的通过项，而非单纯最快返回的地址。高优先级探测未结束前不提前提交低优先级结果。
- 检测使用无认证的轻量健康检查；具体接口须由实施者核实。HTTPS 成功及 HTTP 200 不足以证明 API 可用，需校验预期响应结构。耗时为探测请求总耗时，不是 ICMP ping。
- 全部失败时展示失败原因，允许用户重新检测、编辑或导入列表；不影响其他书源。
- 认证过期、权限不足、额度不足、限流等业务错误不触发地址切换。非幂等操作、可能消耗额度的下载请求不得因切换而盲目重放。
- 编辑、禁用或删除当前地址时清除相关缓存；配置版本变化时丢弃旧探测结果，避免竞态。

## 6. 安全边界

探测客户端与认证客户端隔离，探测不得携带账号、Cookie、Token 或其他凭证。TLS 校验不得关闭；禁止将 HTTP 重定向自动升级为可信地址。跨域重定向不得转发认证头。地址可用不等于身份可信：用户新增或导入地址默认未授权接收既有凭证，认证前需独立验证信任关系；不能仅凭探测成功发送凭证。账号会话按可信服务范围隔离，切换至未授权地址需重新确认或登录。日志脱敏，配置导出不含密钥。拒绝本地、环回、链路本地及私有网络目标，防止探测被用于访问无关内部服务；此限制仅针对该在线检索书源，不改变 WebDAV 的局域网能力。

## 7. 模块与状态管理

建议模块：ServerConfigRepository（读写、迁移、回滚）、ServerDiscovery（探测及选择）、ServerProbeClient（无认证网络层）、ServerSettingsViewModel（列表编辑及状态）、ServerSettingsScreen（界面）。命名和目录以实际静读源码为准。

使用协程与结构化并发，网络和文件 IO 不阻塞主线程。发现任务采用 single-flight，同一配置版本共享检测任务；页面关闭可取消手动检测。配置更新通过版本号防止旧任务覆盖新状态。运行状态包括未检测、检测中、可用、超时、网络失败、证书异常、API 不兼容、已取消。当前使用标记独立于探测状态。

## 8. 实施顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| A | 核实原项目、现有静读配置及网络层 | 输出源码位置、可复用模块和差异 |
| B | 配置模型、持久化、迁移、导入导出 | 配置升级不丢失，非法导入可回滚 |
| C | 无认证探测、缓存及选择策略 | 优先级正确，超时可取消，无凭证泄漏 |
| D | 设置页面及列表管理 | 增删改、启停、排序、单项及全部检测 |
| E | 接入书源网络层及回归测试 | 手动模式不切换，其他书源正常 |

预计额外工作量 5–8 小时为初步估算，实际以现有代码复用程度及测试结果为准。

## 9. 验收清单

- [ ] 新增、编辑、删除、启用、禁用及排序均可持久化。
- [ ] 重复地址、非法地址和无效 JSON 被拒绝。
- [ ] 导入支持预览、合并、替换；导出无敏感凭证。
- [ ] 恢复默认需确认；升级保留用户列表。
- [ ] 单项检测及全部检测正确展示耗时和状态。
- [ ] 禁用项不参与自动检测；全部禁用有明确提示。
- [ ] 缓存未过期时不重复探测；配置变更后旧缓存正确失效。
- [ ] 并发探测遵循优先级，取消和超时不造成状态错乱。
- [ ] 手动模式失败时不自动切换。
- [ ] HTTP 200 的非预期内容不会被判定为可用 API。
- [ ] 探测不携带凭证，跨域跳转不泄漏认证信息。
- [ ] 额度、限流及认证错误不触发无意义的切换或重放。
- [ ] 百度网盘、WebDAV、KOReader 同步、本地阅读及 TTS 回归通过。
- [ ] 静读测试版与正式版继续共存。

## 10. 给 Codex 的执行要求

将本方案作为原在线书库技术方案的增量补充，不改变此前确认的 1–6 项决策（包括文件名唯一去重、重名确认覆盖）。保留现有数据库两张新增表的范围，不为服务器管理增加数据库表。优先复用现有框架，不修改阅读内核、Kokoro、Sherpa-ONNX、原生 TTS、阅读定位及同步协议。先检查实际代码并汇报与本方案的差异，再按当前项目开发阶段安排实施。每阶段执行编译和测试，汇报新增/修改文件、结果及待人工验证事项，不擅自扩大范围。
