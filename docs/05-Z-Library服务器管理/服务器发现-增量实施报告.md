## 1. 本阶段实现的功能

按用户确认的顺序，先完成服务器发现增量 A–E，原方案 D/E/F/G 顺延。本次完成增量 B/C/D/E：

- **B 配置与持久化**：候选服务器对象列表、手动/自动双模式、发现策略参数；schema v1→v2 迁移（旧字符串数组转为启用候选）；地址规范化判重、私有/环回/本地网络拒绝；运行状态独立文件、导入预览（新增/重复/无效）、合并/替换、恢复默认仅重置列表。
- **C 探测与发现**：独立无认证探测客户端（不携带任何凭证、不跟随重定向、校验响应 JSON 结构、拒绝内网目标）；按优先级分批探测（并发 3），选择优先级最高的可用项而非最快；single-flight、TTL 缓存、配置版本防竞态、手动模式不探测。
- **D 界面**：设置页 → 书源设置 → Z-Library → 服务器配置；模式切换、候选增删改、启停、上下移排序、单项/全部检测、重新选择、批量导入/导出、恢复默认（确认弹窗）。
- **E 接入与安全**：凭证绑定服务器主机，切换地址后旧会话自动失效并要求重新登录；探测客户端与认证客户端隔离；额度/认证/限流错误不触发地址切换。

## 7. 已知问题及潜在风险

1. **未做真实服务端实测**：默认候选仍是占位地址 `https://example.com`；健康探测端点 `/eapi/info/domains/singlelogin` 的响应结构校验按参考语义设计，未用真实授权服务器验证。
2. **健康端点结构假设**：`isExpectedStructure` 要求响应对象含至少一个数组或对象字段；若服务端改为纯标量结构可能误判为不兼容。
3. **UI 文本输入未自动化验证**：真机输入法对 URL 中的 `://` 特殊字符处理异常，故「新增/编辑弹窗输入地址」改用配置文件注入方式验证读取链路；输入框实际输入需人工验证。
4. **双层标题栏**：服务器配置页沿用既有二级页面模式（设置页 + 子页标题栏），未做无关重构。
5. **探测并发与超时**：配置上限并发 1–8、超时 1–30 秒；实际网络环境复杂，优先级批次的等待时间可能较长。
6. 参考仓库为 AGPL-3.0，仅借鉴发现策略语义并用 Kotlin 干净重写，未复制 Lua 代码；公开分发/商业化需重新评估许可义务。
