# 轻量语气辅助与对照试听实现

更新：2026-11-23。第三项实现以本文件所在实现提交为准。

## 能力边界

小说解析开关开启、引擎为 Kokoro 且文本解析成功时，才执行规则语气分析。它不提供真实情绪模型，不传入 emotion/pitch/角色标签，不切换用户 SID，也不改变音量。关闭开关后不执行此分析和音频停顿处理。

## 独立分析与规划

源码：`novel-text/.../NovelDelivery.kt`。

`AnalysisUnit` 保留原文、对白状态、段落、跨切块引号状态。`EmotionAnalysis` 输出情绪、表达方式、启发式置信度、规则 ID 和 `novel-delivery-v1` 版本。

- 高置信度明确旁白线索：低声/轻声、急促、怒喝、哭着说等。
- 引号内提到“低声说道”等词不会当作旁白指令。
- 只取同一段落紧邻上下文；不会把另一个完整对白自己的提示词归给当前对白。
- 否定、伪装、冲突、嵌套引号保守回退。
- 只有问号/感叹号的规则分数低于 0.80，不据此自动改变声音。
- 悲伤只标记，保持中性合成参数。
- 少于 6 个文字/数字的片段不单独调整。

规则分数不是统计概率；尚未用人工标注集校准，不能声称达到方案中的自然度或误判率门槛。

## 当前轻微参数

| 表达 | 相对用户速度 | 尾部停顿目标 |
|---|---:|---:|
| 可靠低声提示 | 0.98 | 60 ms；段末 80 ms |
| 可靠急促提示 | 1.02 | 0 |
| 可靠怒喝提示 | 1.01 | 0 |
| 其他/低置信度 | 1.00 | 0 |

绝对合成速度限于现有 UI 的 0.5–2.0。一段内若预计出现超过两次速度变化，整段退回中性，避免频繁变速。用户调速后重新基于用户值计算，不覆盖 DataStore 基础语速。

## 音频停顿处理

`NovelPauseCompensation` 以 5 ms 窗、RMS 阈值 0.001 测量尾部静音。只补不足部分，不删除或裁剪原 PCM；波形末端绝对幅度大于 0.002 时不拼接静音，以避免幅度突变。

单片段新增静音不超过 80 ms，且不超过原时长的 5%。已有静音足够时直接复用原数组。阈值均为实验值，仍需在更多音色和语料中验证。

`core/.../NovelSpeechDelivery.kt` 适配独立模块输出，`speech/.../SpeechCoordinator.kt` 在后台生成每章决策，先检查模型音频健康，再执行有限补偿。Completed 仍由实际播放头越过完整 PCM 边界决定，新增静音也包含在播放边界内。

## 诊断与隐私

SegmentStarted 携带当前片段的语气和音频补偿快照；服务把它写入 SpeechDiagnostics。模型管理面板显示解析版本、表达、置信度、规则 ID、速度系数、补停顿和中性回退原因。

默认只记录索引、长度、规则 ID 和参数，不持久记录书籍正文，不上传文本或音频。没有新增自动 WAV 导出或长期缓存。

## 对照试听

设置中增加“试听当前方式”和“试听解析方式”。两者使用相同的固定自编文本、模型、用户 SID 和基础语速，通过同一个协调器播放。解析方式额外经过新模块和轻微表达规划。

实现：`SherpaKokoroProvider.auditionNovelText()`。朗读/模型正在使用时拒绝并发试听，提示先停止；试听结束、失败、取消均等待 native 安全结束后释放模型租约。

试听按钮不改变开关或用户偏好，不读取当前书籍，不自动导出音频。

## 测试与迭代

测试：`NovelDeliveryTest.kt`、`SpeechCoordinatorTest.kt`。覆盖明确线索、引号屏蔽、否定/冲突、短对白、低置信度、悲伤标签、相邻归属、长对白、频率预算、速度限幅、已有静音、波形安全和关闭路径。

第三项完成时四模块共 194 项 JVM 测试通过，测试版构建及正式版 Debug 编译通过。真机实际效果与长时性能仍需持续评估，自动化测试不能代替盲听。

后续顺序：固定语料 A/B → 校准规则阈值和归属 → 统计 RTF/首声/真实句间空档 → 再决定是否提供标准强度、自定义停顿或更多规则。每次改变规则语义应更新 RULE_VERSION，并确认开关关闭的回归结果。
