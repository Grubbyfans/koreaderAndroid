# 静读 Android：Kokoro 中文小说朗读调优技术方案

> 交付对象：Codex  
> 适用项目：静读 Android EPUB 本地阅读器  
> 现有引擎：Sherpa-ONNX + `kokoro-multi-lang-v1_1`  
> 已知现象：音频播放连续，但中文断句、停顿、重音和语调不自然；设备负载尚未测试。  
> 核心原则：先取证，再小步修改；不更换模型、不引入额外大型模型、不影响正式版安装及数据。

## 1. 目标与非目标

### 目标

1. 定位不自然朗读究竟来自 EPUB 提取、应用文本清洗、分句、Sherpa-ONNX 中文文本前端、模型本身还是音频拼接。
2. 实现可复用的 **TTS 文本调优模块**，与 Kokoro 适配器解耦，未来可供其他引擎复用。
3. 保留中文小说对话、标点、段落的语义上下文；避免过度切句。
4. 建立可复现的 A/B 测试、音频导出、性能和停顿指标。
5. 在不损害 EPUB 阅读位置映射、后台播放、暂停恢复、跳转和朗读高亮的前提下提升自然度。

### 非目标

- 不训练或微调 Kokoro；不引入在线 TTS、LLM 或云服务。
- 不预设某个 SID、`maxNumSentences`、`silenceScale` 必然最优；必须读取实际版本与模型配置并测试。
- 不为消除“语调不自然”而盲目优化 AudioTrack、线程数或缓存。
- 不在未经验证时自动删除所有句首句尾静音。

## 2. 第一步：只读审计与基线

Codex 首先检查项目真实目录、语言、架构、依赖版本和既有测试。不要假设采用某种 Kotlin 类名或前端框架。

按真实调用链追踪：

`EPUB DOM/段落 → 原文提取 → 清洗 → 规范化 → 分句 → TTS 输入 → Sherpa-ONNX OfflineTts.generate → PCM/WAV → 音频队列/播放器 → 高亮与位置映射`

逐项核实：

- `kokoro-multi-lang-v1_1` 模型文件的实际来源、校验值、量化版本、采样率、配套 `voices.bin`、`tokens.txt`、词典、FST、`espeak-ng-data` 等资源是否匹配；以当前版本官方示例和实际加载配置为准，不凭文件名猜测。
- `sid`、`lang`（如 API 支持）、`speed`、`silenceScale`、`maxNumSentences`、线程数和 Sherpa-ONNX 版本；核实 SID 对应音色，不能假设 0 为中文音色。
- 应用是否按逗号、换行、固定字符数分句；是否丢标点、重复规范化；引擎内部是否再次分句。
- 是否每段重新构造模型；播放是否添加额外静音；音频采样率是否正确。
- 是否已有日志、调试菜单、测试脚本与原文偏移映射机制。

**阶段交付**：`docs/03-TTS与语音/tts-audit.md`，包含真实文件路径/函数/行号、调用链、可复现样例、风险和待验证假设。未完成审计不得大规模重构。

## 3. 可观测性设计

新增仅在 Debug 或明确启用的诊断模式下工作的结构化日志；默认不写入完整书籍内容，日志文本截断并允许脱敏，导出需用户主动操作。

建议字段（按现有代码适配）：

```json
{
  "sessionId": "debug-session",
  "chunkId": 12,
  "sourceRange": { "start": 200, "end": 229 },
  "originalText": "他看了看窗外，轻声说道：‘今天，恐怕回不去了。’",
  "normalizedText": "他看了看窗外，轻声说道：‘今天，恐怕回不去了。’",
  "ttsInput": "他看了看窗外，轻声说道：‘今天，恐怕回不去了。’",
  "splitReason": "sentence_end",
  "modelId": "kokoro-multi-lang-v1_1",
  "sid": 3,
  "speed": 1.0,
  "generationMs": 820,
  "audioDurationMs": 4300,
  "rtf": 0.191,
  "leadingSilenceMs": 90,
  "trailingSilenceMs": 180,
  "playbackGapMs": 0
}
```

以上数值和 SID 仅为日志格式示例，不代表推荐配置。

指标定义：

- `RTF = generationMs / audioDurationMs`；若音频时长为 0，不计算。
- `leadingSilenceMs` / `trailingSilenceMs`：根据 PCM 幅度阈值检测，需说明阈值、窗长、噪声底及误差；先测量不自动裁剪。
- `playbackGapMs`：相邻有效语音播放间隔；区分音频本身静音与队列等待。
- 记录分句长度（字符数、可用时 token 数）、生成失败率、P50/P95 RTF、音频队列深度。
- 保留 `sourceRange` 或等价映射，所有调优文本均可追溯原文；不要用规范化文本长度直接计算 EPUB 高亮位置。

## 4. A/B 诊断实验（必须先于优化）

使用固定模型、固定中文音色、固定语速、同一设备；每组重复至少 3 次，记录原始模型 WAV（或无损 PCM）及日志。若 `generate()` 输出 WAV 已不自然，则不要把问题归因于播放器。

| 组别 | 输入策略 | 验证目标 |
|---|---|---|
| A | 完整自然句，一次 `generate()` | 建立韵律基线 |
| B | 同句按逗号拆成多次 `generate()` | 验证过度分句 |
| C | 完整段落，一次生成（不超出模型限制） | 验证上下文收益 |
| D | 数字、日期、英文、人名、引号及省略号 | 验证文本前端 |
| E | 相同文本、不同已核实中文 SID | 验证音色差异 |
| F | 同一原始 WAV 与应用内播放录制 | 区分生成与播放 |

固定语料：

```text
他看了看窗外，轻声说道：“今天，恐怕回不去了。”
“你真的要走？”她低声问道。屋外的雨越下越大。
2026年11月23日，他花了39.8元买了一本书。
韩立皱了皱眉，望着远处的山峰，沉声说道：“看来，我们已经没有退路了。”
```

评测记录：听感主观评分（自然度 1–5、停顿 1–5、发音正确率）、误读词清单、音频时长、静音指标、RTF。尽可能盲听随机排序；不以单次主观感受决定参数。

**判断规则**：A 明显优于 B → 优先改分句；C 优于 A → 增加上下文但控制长度；A/C 都差 → 优先检查中文前端、音色和模型能力；只有 D 差 → 文本规范化；WAV 正常但应用异常 → 播放路径。

## 5. 独立文本调优模块设计

建议抽象（名称仅示例，以项目现有架构为准）：

```text
TtsTextPipeline
  ├─ EpubTextExtractorAdapter  # 复用现有提取逻辑
  ├─ TextNormalizer           # 最小必要规范化
  ├─ ChineseSentenceSegmenter # 语义优先切分
  ├─ TtsChunkPlanner          # 模型长度约束、上下文
  └─ SourceOffsetMapper       # 原文位置映射

KokoroTtsAdapter               # 仅负责模型配置和推理
TtsPlaybackCoordinator         # 保留既有播放/高亮能力
```

建议输出数据：

```kotlin
// 伪代码：实际语言和类型按仓库调整
 data class TtsChunk(
   val id: String,
   val sourceStart: Int,
   val sourceEnd: Int,
   val sourceText: String,
   val spokenText: String,
   val splitReason: String,
   val paragraphId: String
 )
```

### 5.1 分句规则（初始方案，不是最终调参结论）

1. 句号、问号、感叹号及其后随的闭合引号/括号优先作为自然句边界；保留终止标点。
2. 逗号、顿号、冒号、分号默认保留在同一句中；仅当输入超出模型可接受长度时才按优先级回退切分。
3. 识别成对引号、括号、省略号、连续标点；避免把 `“你真的要走？”她问道。` 无条件拆成多个无上下文片段。
4. 不因 EPUB 的视觉换行就强制断句；真实段落边界可作为候选边界，但须尊重语义。
5. 优先遵循模型实际 token/音素限制；字符数（如 60/90/120）只作为可配置实验值，不是硬编码限制。
6. 超长句按 `分号 → 冒号 → 逗号 → 词语边界` 逐级回退；无法安全切分时保留原文并标记风险，避免静默丢字。
7. 分句必须无丢字、无重复、顺序稳定；对原文与合成输入之间的映射保持可追踪。

### 5.2 文本规范化

- 优先使用当前 Sherpa-ONNX 中文文本前端已支持的词典、FST 和发音转换，**避免应用层与引擎层重复展开数字**。
- 对日期、金额、百分比、电话、英文缩写、人名、多音字分别建立测试语料；仅在证实默认前端有缺陷时加入小范围规则。
- 保留问号、感叹号、冒号、引号等可能影响韵律的标点；禁止一刀切删除所有标点。
- HTML 实体、注音、脚注、隐藏元素、重复空白按 EPUB 提取层的实际行为处理，避免破坏正文。
- 自定义多音字词典作为可选后续能力，必须与模型支持的输入形式兼容，不直接向模型传入未经支持的拼音控制标签。

### 5.3 停顿与音频边界

- 第一版只统计，不改变首尾静音；确认句间停顿过长后，再尝试轻量裁剪与标点分级停顿。
- 不要跨句硬拼接造成爆音；若需要处理 PCM 边界，先做零交叉/短淡入淡出测试。
- 句间停顿与段落停顿分开配置；避免在模型已生成停顿后再次叠加同等时长。
- 不承诺通过规则直接控制“愤怒/悲伤”等情绪；Kokoro 若无对应可验证接口，不增加伪参数。

## 6. 实施阶段与验收门槛

### 阶段 A：审计和诊断（不改变朗读结果）

- 完成调用链审计、配置核对、诊断日志和 WAV 导出。
- 完成 A/B 测试并输出报告。
- 验收：可根据 `chunkId` 找到原文、最终模型输入和对应音频；现有功能无回归。

### 阶段 B：最小分句修复

- 仅针对已证实的过度分句、标点丢失或重复规范化修复。
- 引入可回退的 `legacy` / `semantic` 策略开关（Debug 阶段），默认行为先保持不变。
- 验收：测试语料无漏字、重复、乱序；完整句生成自然度不低于基线；高亮和跳转正确。

### 阶段 C：中文规范化与韵律调参

- 仅对已复现的误读补充规则；针对中文 SID、语速、`silenceScale` 等逐项 A/B。
- 验收：同设备、同语料的盲听评分较基线改善；不得引入明显新误读。

### 阶段 D：性能与稳定性

- 在 Android 目标设备上采集 CPU、内存、发热、线程数、RTF、连续朗读 30 分钟后的指标。
- 仅在证实推理/缓冲瓶颈时改造预生成队列或缓存。
- 验收：暂停/恢复、上一句/下一句、章节切换、后台播放、锁屏、来电/音频焦点等无回归。

## 7. 自动化测试清单

- 中文标点：`。！？；：，、……“”‘’（）`、连续标点、引号嵌套。
- EPUB：跨标签句子、空段落、软换行、脚注、章节标题、隐藏文本。
- 长文本：超长无标点、超长引号、连续英文、混合数字。
- 规范化：日期、金额、百分比、小数、序号、英文缩写、多音字。
- 一致性：所有分句重组后与原文可见文本一致（允许明确记录的空白规范化）；任何失败不得丢句。
- 位置：每个 `TtsChunk` 可回溯原文范围，朗读高亮、跳转、恢复位置保持正确。
- 回归：切换音色/语速、暂停、停止、跳句、切章节、屏幕熄灭、应用后台、进程重启。

## 8. Android 打包与安全约束

- 若项目已有“静读测试版”独立包名/应用名机制，必须沿用，确保可与正式版并存；检查 `applicationId`、应用显示名、签名及数据目录隔离。
- 若尚未配置独立测试包，先向用户报告并优先以 Debug 构建验证，不覆盖正式版。
- 不删除或迁移用户书籍、阅读进度、批注和正式版数据库。
- 不新增网络上传；诊断 WAV/文本仅本机存储，设置容量上限和清理入口。
- 不擅自升级大型依赖、替换模型、改动非 TTS 模块。

## 9. Codex 执行规范

1. **先完成阶段 A 并汇报，不自动进入 B–D。**
2. 任何结论必须给出仓库文件路径、函数/行号、日志或可复现实验，不可猜测。
3. 对无法验证的模型配置和参数明确标记“待验证”；以当前项目实际 Sherpa-ONNX API 为准。
4. 每个阶段分别提交小范围变更，执行现有 lint、类型/编译检查、单元测试和 Android 构建；报告通过、失败、未执行及原因。
5. 不擅自更改产品范围；若需要增加新依赖、调整模型文件或修改数据结构，先报告利弊并等待确认。
