# 小说文字解析模块实现

更新：2026-11-23。基础实现提交：`3b8f5d0`；语气上下文元数据随第三项补充。

## 职责与边界

独立 Gradle 模块 `:novel-text`，核心源码位于 `novel-text/src/main/java/com/yuezhou/reader/noveltext/`。使用仓库已有 AGP/Kotlin 工具链构建，解析代码没有 Android、EPUB、网络、Sherpa-ONNX 或播放器 API 依赖。模块只处理文本与来源位置，不加载模型、不修改书籍、不保存阅读进度。

构建配置：`novel-text/build.gradle.kts`；模块注册：`settings.gradle.kts`。新模块不直接依赖 `:core`，由 `:core` 适配其输出，避免循环依赖。

## 数据契约

`TextSource`：文本节点内容、nodeId、节点内起始偏移、是否结束段落。

`NovelChunk`：

- `originalText`：原文片段，保留字符及标点。
- `spokenText`：仅清理零宽字符及重复空白后的文本；最终 Kokoro 兼容清洗由引擎接入层执行。
- `sourcePoints`：每个原文 UTF-16 字符的位置及末位边界，长度等于 `originalText.length + 1`。
- `sourceSpans`：连续节点范围，终点为 exclusive。
- `paragraphId`、`paragraphBoundaryAfter`：段落归属及结束标记。
- `dialogue`、`quoteCloserAtStart`、`nestedQuotes`：对白及跨切块引号上下文。
- `splitReason`、`parserVersion`：切分原因及策略版本。

所有偏移是 **UTF-16 代码单元**，与 Kotlin String、JavaScript DOM Range 一致；不是 Unicode 码点数量。不得使用 spokenText 长度定位或高亮。

## 分句算法

入口：`NovelTextParser.parse()`。

1. 同段落内的行内节点依次连接，同时保留每个节点自己的位置。
2. 有限状态扫描成对引号和括号，保留完整对白上下文。
3. 疑问对白后紧接的“她低声问道”等归属短语可保留在同一分析片段。
4. 句号、问号、感叹号是候选边界；连续标点和右引号归入前句。
5. 小数、点号日期和常见英文缩写不从点号中间切开。
6. 过长时依次尝试分号、冒号、逗号、空白；最终按长度兜底，避免拆开 UTF-16 代理对。
7. 普通逗号、冒号、分号、省略号不会被无条件分句。

当前默认 `maxChars=120`、`minChars=12`。这只是实验性字符预算，不是 Sherpa 的 token 硬上限，也不是已证明的最优参数。短句可合并，因此开启后上一句/下一句及高亮的粒度是解析片段。

版本：`NovelTextParser.VERSION = 1001`。现有 legacy 分句版本仍为 2。修改可影响分句结果的规则时必须更新解析版本。

## 位置与复杂度

扫描、切分和位置构造以段落为范围，连续标点扫描避免重复回看整个标点串。当前仅处理请求章节，不整书预处理。位置表仍按字符保存，超大章节的内存成本需要继续测量。

`core/.../SpeechTextPlanning.kt` 把模块位置转换成 `SourceAnchor`。语义解析片段查找锚点时排除末位 exclusive 边界，避免前一句抢占下一句起点；旧策略的查找契约保留。

测试：`novel-text/src/test/.../NovelTextParserTest.kt`。

覆盖完整对白、后置归属、小数/日期/英文缩写、嵌套引号、跨节点偏移、长句回退、无标点超长文本、emoji、零宽字符、空输入和段落隔离。

```sh
./gradlew :novel-text:testDebugUnitTest
```
