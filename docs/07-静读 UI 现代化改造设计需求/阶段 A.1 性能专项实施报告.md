| 设备 | Samsung SM-S9360，Android 16 / API 36，1080×2340。性能轮次固定 60 Hz，保留设备原设置并在完成后恢复。另一隔离包在启动轮次中停止运行。电池温度逐次记录，保留异常慢样本。 |
| ART 与缓存 | 两个隔离包均使用 `cmd package compile -m speed -f`。每次 `am force-stop` 后从相同 Activity 入口启动。系统文件缓存不通过 root 清空，以 AB／BA 交错次序平衡缓存和温度变化。样本的 ART 条件与阶段 0、A 原本的分日测量不同。 |
| 三种读数 | Activity `am start -W` 的 TotalTime 对应 Android 报告的此次 Activity 显示时延；首帧额外记录 Window FrameMetrics 单帧耗时和自 onCreate 起至首帧回调时间；书库可交互代理值取加载标记转为就绪后的第二个 Compose 帧，从 onCreate 起算。代理值不等于硬件输入到像素的端到端时延，另以真机点击验证页面可进入。 |
| Trace | 分开采集 Perfetto 和可直接复算的 atrace 文本。启动配对样本不在 Trace 录制下执行。探针标记 `A1.ShelfReady` 与 `A1.HeadingTypeface` 暂留于隔离 APK，用于关联时序。 |
| 内存 | 通过 `dumpsys meminfo` 采样主进程，在书库、云端、阅读器初始、面板反复开关、闲置及多次重开时记录 PSS 和分类。WebView 的沙箱渲染进程、Bitmap 私有分配和 GPU 驱动内部细分未独立归属。 |

## 5. 优化实验、取舍与回滚

系统衬线对照与未压缩 OTF 对照在临时独立包实施。未压缩版复用了同一份 Noto Serif SC 文件及后台加载代码，验证 APK 对应 ZIP 条目的方法从 Deflate 变为 Store。字体读取中位数从 71.21 ms 降至 2.29 ms（约 −96.8%）。书库 Java Heap 从 28.8 MiB 降至 17.9 MiB，接近系统衬线对照的 18.0 MiB。这支持压缩字体读取与约 11 MiB Java Heap 差额有关。Graphics 三者相同，未压缩版较高的 Code/映射 PSS 抵消了 Java Heap 节省。此对照不提供完整堆对象分配归因。

| 字体对照结果 | 阶段 A （压缩资产） | 未压缩同一字体 | 系统衬线对照 |
| --- | ---: | ---: | ---: |
| 字体读取中位 | 71.21 ms | 2.29 ms | 不加载资产 |
| 首次书库总 PSS | 132.0 MiB | 135.3 MiB | 134.5 MiB |
| 书库可交互代理中位 | 413.89 ms | 430.83 ms | 397.46 ms |
| Activity 中位 | 314.0 ms | 364.0 ms | 347.5 ms |

字体对照是单独的六轮序列，热状态高于部分主配对轮次，三个变体均出现慢样本。它证明了字体读取策略对**局部耗时和 Java Heap**有影响，但未压缩版没有证明用户可感知启动或总 PSS 能同时获益，其字体条目还增加约 1.64 MiB。系统衬线版仅用于拆分影响，实际交付继续保留已确认的中文字体。

**未将实验代码合入项目。** 仍以阶段 A 已交付的 `7ec4a0d`（异步加载并进程内缓存）为交付版本。A.1 无应用代码提交、版本号或业务变更；无需回滚正式版或测试版。如需清理，只移除四个 `.perfbase`、`.perfa`、`.perfsystem`、`.perfmapped` 隔离包及其合成数据。采集完成已恢复设备原刷新率设置；正式版 `0.1.5` 和正常测试版 `0.1.6-tts-test` 的安装记录均未改变。

## 6. 功能回归、截图与待评审结论

- 同一源码的正式及测试变体重新构建成功，并运行了全模块 `test` 及两变体 Lint 任务。Gradle 共 444 个任务，其中 440 个使用已是最新的结果；应用代码和原测试基线相同。本轮重新执行阅读 Web 测试，4 项通过。
- 真机隔离包验证了四本样例书、书库到云端及返回、EPUB 正文、每个版本的 30 轮面板操作和 10 次进出阅读器。当前包号与功能结构保持阶段 A 状态。本轮云端使用未配置状态，未重新验证远端授权、跨设备同步、实际下载或 Kokoro。
- 证据包中 `candidate-书库.png`、`candidate-云端.png`、`candidate-阅读正文.png` 为最新阶段 A 源码的隔离包实拍；另保留基线截图、本轮字体对照、启动 CSV、原始日志、内存分类、Perfetto 与 atrace 文件。测试用探针源码另附。
- **启动**：以可比主配对为准，Activity 中位为基线的 104.9%，首屏可交互代理为 118.1%。原先 135% 的启动增幅未复现，无法反推出原差异中 ART、温度、入口和安装态各自占比。
- **内存**：书库 121.0 → 135.5 MiB、云端 148.2 → 163.8 MiB，分别约 112% 和 110.5%，略高于参考线。阅读器初始 226.2 → 244.3 MiB、闲置 228.7 → 250.1 MiB，均在 110% 内。10 次重开时的 PSS 仍较高，退出闲置后两包均回落。此轮只证明短时表现，不支持宣称有或没有泄漏。若评审要求继续收敛，下一轮需固定热状态并用堆分配追踪分解字体、映射、位图及 WebView。
- WebDAV 提示、云端竞态、设置并发及后续测试环境继续按评审指定阶段处理。阶段 B 未开始。
