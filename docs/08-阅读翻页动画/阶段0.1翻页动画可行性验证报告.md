# 阶段 0.1 翻页动画可行性验证报告

日期：2026-11-26。结论：**独立预览获取相邻页的路线可行，但建议暂缓进入阶段 A，先收敛未命中捕获的主线程开销与内存策略。** 本阶段未接入正式翻页功能，未移植 iOS 算法，未修改阅读引擎。

## 1 验证范围与环境

实机为三星 SM-S9360，Android 16 / API 36，WebView `134.0.6998.135`，物理分辨率 1080×2340、density 450。扣除系统栏后的阅读视口为 384×754 CSS 像素；三张 ARGB 快照实际合计 27,488,160 字节，约 26.21 MiB。

验证入口仅存在于 `app/src/ttsTestDebug/`，运行于 `:pageprobe` 进程。使用现有 `ReaderWebView` 和 **APK assets 中的定制 foliate-js**，不使用 vendor 旧副本。预览 WebView 保持真实布局、非透明，挂载在主 WebView 下方；没有使用 GONE 或零尺寸离屏视图。

书样为两份原创合成 EPUB，每本三章，包含中文、拉丁字母、标点和 SVG 图片；第二本正文含不同标识，用于真实换书验证。测试覆盖默认字体、内置思源宋体、霞鹜文楷、系统等宽字体，以及浅色、深色、米黄、护眼主题。主书样 SHA-256 为 `918ef9ef5a06afec0a491573b8ff0e4165540cbf3a1cbb05d1ba1d17d8ff5082`。

最终完整采样耗时约 33.3 秒，包含主动 GC、主机内存采集等待和生命周期循环，不代表用户翻页耗时。以下数值统一来自最终一轮；调试期间修正了系统栏捕获边界、主机采集脚本和帧时钟基准，不混用早期失败采样。

## 2 页面与快照一致性

| 验证项 | 实测结果 |
| --- | --- |
| 当前页、下一页、上一页 | 主/预览页首 CFI 与可见文本一致 |
| 跨章节向后与向前 | 邻章首页和原章末页均一致，无错章 |
| 字体、排版、主题、图片 | 共 11 组对照，页首 CFI、可见文本及两份软件快照逐像素相同；样例图片正常出现，无全白/全黑捕获 |
| 捕获与屏幕显示 | 对浅色图片页、深色字体页另做窗口 PixelCopy；不同像素比例为 3.10% / 2.38%，平均 RGB 通道误差为 0.0325 / 0.0329（0–255），目视未见内容错位或漏图 |
| 换书后预览 | 清理旧实例与缓存，主 WebView 实际打开另一本 EPUB；新预览继承当前书籍、字体和主题，重新定位时校验可见文本一致 |

快照路径为等待字体与图片就绪、双 requestAnimationFrame、`postVisualStateCallback`，再执行 `WebView.draw(Canvas(bitmap))`。主/预览软件快照相同不能代替屏幕一致性，所以单独做了上述 PixelCopy 对照。窗口和软件绘制并非位级相同；这里仅确认所测书样没有明显显示差异。

**未验证**：用户导入字体、复杂照片/大图、视频、公式、fixed-layout EPUB、RTL、损坏/慢加载资源和其他 WebView 版本。本轮不将合成书样结果外推到全部 EPUB。

## 3 时延与预加载

| 测量项 | 最终实测 |
| --- | --- |
| Activity 启动至主页面就绪 | 646.2 ms，其中主 WebView 创建到页面就绪 630.7 ms |
| 首次预览创建至就绪 | 524.6 ms；后续重建为 529.6–544.2 ms |
| 首次页面捕获 | 66.5 ms，其中 Bitmap 分配与同步 draw 为 17.0 ms |
| 全部页面捕获，30 次 | 中位数 55.0 ms，范围 46.5–67.0 ms |
| 同步分配与 draw，30 次 | 中位数 27.3 ms，范围 16.4–35.5 ms |
| 首次跨章下一页预加载 | 246.2 ms，其中目标快照捕获 61.7 ms |
| 下一页优先准备、随后上一页 | 分别 237.5 / 232.2 ms，完成后才开始缓存响应实验 |
| 缓存检索，40 次 | 中位数 0.018 ms，P95 0.022 ms |
| 缓存命中，合成 MOVE 至首帧绘制，20 次 | 中位数 7.0 ms，P95 7.8 ms，最大 8.4 ms |
| 缓存命中，合成 UP 至首帧绘制，20 次 | 中位数 7.4 ms，P95 8.4 ms，最大 8.4 ms |

进程冷启动通过强停测试应用后运行获得，未清除 Chromium 磁盘缓存。捕获包含 JS 资源就绪、视觉同步、Bitmap 分配与 draw；预加载还包含定位和原 paginator 在无动画翻页时的等待，不等于纯 EPUB 排版耗时。

缓存命中的合成输入到覆盖层 `onDraw` 已低于 33/50 ms 目标，**尚不是正式手势、真实显示提交或动画启动的端到端达标结论**。本实验只显示缓存位图，没有提前制作渐变或卷曲动画。

受控预加载顺序已经验证为“下一页优先、再上一页”，缓存最多 current/previous/next 三张；不是等合成输入发生后再加载。但仍有问题：预览加载可异步等待，最终软件捕获仍同步占用宿主主线程。六次预加载期间有两次出现超过 33 ms 的帧间隔，最大 33.38 ms；首次跨章和优先预加载分别最大约 25.03 ms。它证明当前路径存在掉帧风险，**“未命中不得阻塞主阅读界面”尚未通过**。不能仅用协程或“后台预加载”描述消除这一开销。

## 4 单 WebView 与双 WebView 内存

单位为 MiB。Java/Native 是验证宿主的已分配堆；PSS 分别由 `dumpsys meminfo` 对宿主及按应用 UID 关联的 WebView 沙箱进程采集。采样之间存在短暂时间差，堆分配量不能与 PSS 直接相加。

| 状态 | Java 堆 | Native 堆 | 宿主 PSS | 渲染器 PSS | 合计 PSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单 WebView，首次页就绪 | 3.56 | 19.39 | 200.63 | 75.42 | 276.05 |
| 双 WebView，尚无保留快照 | 3.52 | 20.02 | 210.96 | 90.03 | 300.98 |
| 双 WebView，多轮捕获并保留三张快照 | 3.72 | 48.74 | 287.17 | 152.57 | 439.74 |
| 切回旧模式，释放预览与快照 | 3.94 | 22.45 | 271.50 | 148.55 | 420.05 |
| 所有 WebView 释放 | 3.99 | 19.80 | 215.30 | 未发现关联沙箱 | 215.30 |

第二个 WebView 刚创建时合计 PSS 增加约 **24.9 MiB**。多轮主题、章节和捕获后增加的内存还包括 Chromium/字体/图形缓存，不能全部归因于三张 26.21 MiB 位图，也不能认为生产只会增加 25 MiB。

清理位图后 Native 堆从 48.74 降到 22.45 MiB，快照池字节数归零；但 PSS 没有立即回到单 WebView 水平。后三次重建/释放后的合计 PSS 约为 398.8 / 406.8 / 392.2 MiB，没有单调增长，但样本不足以证明长期无泄漏。低内存设备、长书和长期阅读压力**未验证**。

## 5 副作用与资源释放

| 验证项 | 证据与结论 |
| --- | --- |
| 主页面进度隔离 | 11 组预览比对和 6 次预加载期间，主 WebView 的 relocate 增量均为 0，主 CFI 未被预览改变 |
| 数据库 | 测试应用已有主数据库、WAL、SHM 三个文件的运行前后 SHA-256 全部不变 |
| 同步与 TTS | 独立进程经现有 Application 守卫跳过 RoomSpeechProgressSink/TTS 装配，预览回调不接进度或同步端口；结束时应用服务列表为空。验证宿主没有调用真实同步/TTS；正式阅读中同时播放/同步的端到端场景未验证 |
| 切回旧模式、换书、退出 | 验证宿主调用统一清理：移除 View、`ReaderWebView.release()`、清空并回收 Bitmap；实际换书成功，旧缓存未复用 |
| WebView 生命周期 | 共创建并销毁 5 个 WebView（主 1、预览 4）；最终 dumpsys 的 WebViews 为 0，4 个预览弱引用在函数返回并等待 GC 后全部归零 |
| Activity 退出 | 通过返回键退出至桌面；仍为 0 个 WebView。进程可继续被系统缓存，不把进程 PSS 未归零判为资源仍在使用 |

生命周期检查发生在最小宿主中。正式 ReaderActivity 的模式切换、换书、后台和 TTS 接线尚未改动，因此相应生产场景仍待阶段 A/C 验证，不能用实验宿主的释放结果替代正式集成验收。

## 6 许可证与改动边界

本阶段没有复制任何上游动画源码。参考 ZIP 及其许可证未修改，来源记录已补入 `docs/01-工程与构建/third-party-notices.md`。

后续可优先复用附 MIT 的 `feature/reader/core/transition/ioscurl/` 核心目录（21 个 Kotlin 文件及 Peyilo 版权许可）。位于该目录之外的 `IosCurlTurn`、`IosCurlPageStack`、平台渲染器及渐变/Surface 代码没有同样的独立 MIT 声明，继续保守按项目 GPL-3.0 处理。PageCurl-Core `c23fd9d`、PlayLikeCurl `915a5a3` 的 MIT 记录不扩大到整个动画栈。

按已确认的个人使用背景，后续无需为了回避 GPL 另写近似算法；仍须保留适用许可证、逐文件来源及修改记录。个人使用背景不替代未来分发时的许可处理。

新增代码仅为 `app/src/ttsTestDebug/` 下的验证 Activity、JS 和两份合成 EPUB，以及 `tests/` 下的生成/运行脚本。生产阅读代码和设置没有改动；正式渠道主清单检查未包含验证入口。测试版已更新安装，应用数据保留，验证结束后已退出至桌面。

构建 `:app:assembleTtsTestDebug` 成功，既有 Node 阅读桥接测试 **6/6 通过**，实测结果断言通过。原始结果只保留在本地 `build/page-preview-probe/final/`；复现入口见 `tests/fixtures/page-preview/README.md`，不再生成重复截图报告。

## 7 是否建议进入阶段 A

**暂缓。** 页面一致性、跨章、缓存命中的轻量绘制和实验隔离均已获得实机支持，核心路线不需要推翻；但同步整页捕获和捕获后的内存驻留尚不满足稳妥开放功能的条件。

下一步建议仅补充一项收敛验证：比较可用的异步/硬件捕获路径或捕获调度，明确未命中时立即保持现有阅读交互的回退行为，并验证低内存下的字节预算和预览释放策略。不能默认把软件 draw 放到工作线程，也不能把预览 View 改成不可见后假设仍可捕获。若这些验证要求调整已批准的页面适配路线，应先说明差异再实施。

待上述问题收敛并获评审确认后，再进入渐变翻页阶段 A。本轮停止于阶段 0.1，不继续正式功能开发。
