# 静读翻页动画移植技术实施方案

日期：2026-11-26。状态：已通过有条件评审，获准阶段 0.1 补充验证；阶段 A 尚未获准。

## 1 调研结论与源码基线

建议保留静读的 WebView 与 foliate-js 阅读体系，增加页面快照适配层，移植 Legado-with-MD3 的 iOS 卷曲算法及必要渲染器，并提取其渐变策略。无需替换 EPUB 解析、分页和 CFI/XPointer 定位规则。

**可行性为源码层面的有条件可行。** 两个主要前置条件是：验证 WebView 相邻页捕获与真实翻页的一致性；确认 GPL 代码的采用及分发方式。未经验证，不能承诺所有设备达到 60 FPS，也不能把“独立模块”视为解除 GPL 义务的依据。

## 2 两种动画的真实实现

### 2.1 iOS 仿真

入口是 `R/ReaderCanvasSurface.kt`，模式为 `ReaderTransitionMode.IOS_CURL`。`app/src/main/java/io/legado/app/constant/PageAnim.kt` 中值为 **6**；普通仿真值 2 对应另一套实现，不是本期的 iOS 效果。

| 真实路径 | 核心职责 |
| --- | --- |
| `R/components/ioscurl/IosCurlTurn.kt` | `IosCurlTurn`：触点转换、手势识别、起卷、拖动、完成和取消、帧时钟 |
| `R/components/ioscurl/IosCurlPageStack.kt` | `IosCurlPageStack`、`IosCurlGraphics`：双页捕获、渲染路径选择、TextureView 生命周期及失败兜底 |
| `R/core/transition/ioscurl/model/CurlModel.kt` | 页面尺寸、装订方向、卷曲配置、进度/半径/角度等值模型 |
| `R/core/transition/ioscurl/control/CurlControl.kt` | 起卷值、触点到形变值的映射、端点和速度相关收尾时长 |
| `R/core/transition/ioscurl/control/CurlTiming.kt` | `CurlTiming`：进度、半径和角度的三次贝塞尔插值 |
| `R/core/transition/ioscurl/gesture/CurlPan.kt`、`CurlNavigation.kt` | `CurlPan` 等：识别方向、速度、是否完成，处理手势状态 |
| `R/core/transition/ioscurl/layout/CurlLayout.kt` | `CurlLayout`：前后翻页的纹理角色、底页和绘制布局 |
| `R/core/transition/ioscurl/mesh/CurlMesh.kt` | `CurlMesh`：输出顶点、索引及绘制批次 |
| `R/platform/ioscurl/IosCurlRenderer.kt` | `IosCurlRenderer`：GLES2、EGL、纹理上传、窗口输出及位图输出 |
| `R/platform/ioscurl/IosCurlCanvasRenderer.kt` | `IosCurlCanvasRenderer`：API 34+ 硬件 Canvas Mesh 快路径 |

必须随核心一起保留的算法文件是 `math/BinaryMath.kt`，以及 `mesh/generation/` 下的 `CurlCurve.kt`、`CurlProjectionBuilder.kt`、`CurveSampling.kt`、`DrawBatchAssembler.kt`、`LinearTransform.kt`、`MeshBuildContext.kt`、`MeshConstants.kt`、`MeshGenerator.kt`、`PackedHalfColor.kt`、`PageSurfaceBuilder.kt`、`PenumbraBuilder.kt`、`ShadowBuilder.kt`、`VertexBuffer.kt`。它们共同承担曲面采样、投影、纸背、阴影、半影及颜色精度，不能只拿一个变形函数替代。

工作链路：

```text
触摸坐标与时间 → CurlPan → CurlControl / CurlTiming
                                      ↓
两页快照 → CurlLayout + CurlMesh → Canvas Mesh 或 GLES → 屏幕
                                      ↓
                    动画完成后宿主提交翻页；取消不提交
```

原版 `IosCurlTurn` 将像素除以 density 转为逻辑坐标，时间从毫秒转为秒；手势误触设置映射为 `sloppiness`。自动翻页原生 400 ms 按统一速度档位归一，默认完整翻页 **360 ms**，其余档位为 240/300/540 ms。手动收尾使用 `CurlControl.duration` 与原贝塞尔曲线，不能统一改成固定时长的普通 tween。起卷曲线、Float 舍入及半精度颜色处理一并保留。

原版两页栅格化在动画循环外；每帧更新形变和合成。API 34+ 且背景不透明、硬件 Canvas 满足条件时走 Mesh，否则走 GLES。GLES 优先直接输出 TextureView，工作线程最多保留一帧待处理姿态；位图读回路径涉及 `glReadPixels`，仅宜兜底。原版等待页面捕获有 30 帧上限，最终还可退到页面快照；适配层需另有页面准备超时，不能把这个渲染器等待上限当成完整加载超时。

### 2.2 渐变

本包真实执行链为 Compose 实现，不能仅凭旧类名查找 `FadePageDelegate`。该名字出现在注释中，实际依据如下：

| 真实路径与位置 | 行为 |
| --- | --- |
| `R/core/transition/ReaderPageTransition.kt`，`fromPageAnim` | 值 **4** 映射 `FADE` |
| 同文件 `ReaderPageTransition.progress`、`transforms`，约 245/260 行 | `p = abs(offsetPx) / pageExtentPx`；当前页 alpha 保持 1，目标页 alpha 为 p，向前目标为 previous，向后为 next |
| 同文件 `settleDurationMillis`，约 150 行 | 渐变收尾使用完整基准时长，不按剩余位移缩短 |
| `R/ReaderCanvasSurface.kt`，约 1569 行 | 渐变松手阈值 0.1，速度传 0，不采用最后拖动方向作为提交条件；取消不提交 |
| 同文件约 618/631 行 | 收尾使用 `FastOutSlowInEasing` 与 `Animatable.animateTo` |
| 同文件约 1732–1824 行 | 当前页先画，目标页后画，`graphicsLayer` 修改目标透明度，避免逐帧重画正文 |
| `R/core/transition/ReaderPageTurnSpeed.kt` | 默认 360 ms，与其他速度档位共享基准 |

因此源码确认它是**完整目标页面覆盖在当前页面上逐渐显现**，不是空间渐变遮罩，也不是两张页面同时降低 alpha。目标页必须包含主题背景，否则文字会重叠。可以用等价的位图 alpha 合成承载，但必须沿用上述图层顺序、交互阈值、时长、插值和提交规则；仅给 WebView 设置透明度不等价。

## 3 静读与参考项目的架构差异

| 维度 | Legado-with-MD3 本包 | 静读现状与适配影响 |
| --- | --- | --- |
| 内容生成 | Kotlin 原生页面模型，`R/core/model/ReaderPage.kt` 的 `ReaderPage`、`ReaderPageId`、`ReaderPageWindow` | EPUB 在 WebView 内由 foliate-js 排版，不能直接转成上游原生元素模型 |
| 相邻页 | `ReaderPageWindow` 持有 previous/current/next 等页面，可包含邻章占位页 | paginator 主要维护当前章节视图，没有可调用的相邻页 Bitmap/peek 接口 |
| 绘制 | `ReaderPageCanvas`、Compose GraphicsLayer，可直接录制页面 | `reader/.../ReaderWebView.kt` 嵌入原生 WebView；Compose GraphicsLayer 不能直接替代 WebView 捕获 |
| 分页与章节 | 宿主返回新的页面窗口 | `reader-web/vendor/paginator.js` 的 `#turnPage`、`#goTo` 负责翻页和加载；邻章加载可卸载旧章节 |
| 手势 | `ReaderCanvasSurface.kt` 仲裁，再交给 CurlPan 或通用策略 | Kotlin 处理单击区域、左侧亮度；横滑/缩放/选择主要在 WebView/JS 中处理 |
| 位置 | 以原生页面 id 和宿主提交为基础 | CFI、章节、fraction 经 bridge 的 `relocate` 回 Kotlin，关联保存和同步 |
| 缓存 | `PageSnapshotBitmapPool` 最多 3 张；key 含页面/排版/背景等版本 | 没有等价动画快照池；需建立有界缓存，不能引用原生元素 key |
| TTS | 原生阅读模型相关联 | `speech-highlight.js` 可直接 `view.goTo` 或 `renderer.scrollToAnchor`，不会经过 Kotlin `nextPage()` |

静读的具体接点：

- `app/src/main/java/com/yuezhou/reader/ReaderActivity.kt:827` 创建正文 WebView；约 834 行的区域点击调用 `nextPage/prevPage`。
- `reader/src/main/java/com/yuezhou/reader/reader/ReaderWebView.kt` 桥接到 `window.__reader.next/prev`；其触摸监听目前允许横滑进入 WebView。
- `app/src/main/assets/reader/bridge.js:95` 调用 `view.next/prev`；约 301 行只识别 `none`，其他模式都会启用 slide，新增模式须避免双重动画。
- 实际随包运行的 `app/src/main/assets/reader/paginator.js:953` 通过 `slidePage` 使用 Web Animations，分页滑动为 **220 ms**、`cubic-bezier(.2,.65,.35,1)`；滚动模式使用浏览器 smooth scroll。约 874 行起处理 JS 横滑；已包含 AbortController 和翻页锁的 finally 释放。
- `app/src/main/assets/reader/bridge.js:463` 将可见范围折叠为页首 CFI；`ReaderActivity.kt:668` 接收后更新位置，并在 300 ms 去抖后保存，还会进入自动同步判断。**预览页不能发进这个链路。**
- `app/src/main/java/com/yuezhou/reader/ReaderSettings.kt` 已使用 DataStore 保存 `pageAnimation`，默认 `slide`；阅读设置约在 `ReaderActivity.kt:1423`，已有“无/滑动”。

`reader-web/README.md` 说明 vendor 为构建源，但本次查看 Gradle 脚本未发现自动复制任务，且两处 paginator **已经不同**：vendor 仍为 300 ms 的 `easeOutQuad` 路径，assets 另有滑动、手势和滚动跨章定制。以 assets 作为运行行为依据，不能用 vendor 覆盖 assets。后续如增加手势钩子，应明确两处的来源关系并保留定制；本方案不调整分页算法。

## 4 复用与适配边界

以下是技术划分，实际复制以第 9 节许可证门槛为前提；本轮实际复制到产品中的模块为零。

| 分类 | 模块 | 处理方式 |
| --- | --- | --- |
| 可直接复用算法 | `core/transition/ioscurl/` 全部 21 个 Kotlin 文件及本目录 LICENSE | 保留数学结构、常量、采样、手势模型；主要改包名，不引入上游阅读引擎 |
| 可少量适配复用 | `platform/ioscurl/IosCurlRenderer.kt`、`IosCurlCanvasRenderer.kt` | 输入仍是两张 Android Bitmap 与同一网格；核对 API、线程和资源归属 |
| 需适配复用 | `IosCurlTurn.kt`、`ReaderPageTurnSpeed.kt` | 替换方向类型、宿主事务和就绪回调；保留时钟、坐标、曲线及速度缩放 |
| 需提取并适配 | `IosCurlPageStack.kt` 中 `IosCurlGraphics` 和显示逻辑 | 保留 Mesh/GLES 选择及渲染生命周期；将原生页面捕获改为 WebView 快照输入 |
| 需提取并适配 | `ReaderPageTransition.kt` 的渐变分支及 Surface 对应释放/收尾逻辑 | 沿用原公式和参数，去除不在本期的模式；不要复制整个 Surface |
| 无法原样复用 | `ReaderPageCanvas`、原生 `ReaderPageWindow`、`PageSnapshotLayer`、原版快照 key 和就绪检查 | 依赖原生排版和图元；新增 WebView 页面提供器、版本 key 和资源就绪协议 |
| 不纳入本期 | 上游分页器、章节仓储、数据库、选择系统、TTS、其他翻页效果 | 保留静读能力，避免引入无关依赖 |

整套上游页面栈不能直接粘贴：它要求可组合的 `ReaderPage` 和 GraphicsLayer，静读提供的是 WebView DOM。障碍影响的是**页面生产与捕获接口**，不影响卷曲数学和双 Bitmap 渲染接口。建议只替换该接口；不采用重新画一套近似卷曲、也不将 foliate-js 改造成原生分页器。

## 5 推荐接入方案

### 5.1 页面提供与模块组织

在 `reader` 模块建立独立的 `animation` 包，负责两页快照、动作状态和绘制；Compose 外层接入留在 `app`。优先保留现有 Gradle 模块划分，不为本期增加通用插件框架。原算法在 `reader` 中保持纯 Kotlin，Compose 控制/覆盖层放 `app`，避免把 Compose 依赖扩散到现有 reader 库。

```text
现有主 ReaderWebView / foliate-js ── 已提交 CFI ── 现有保存与同步
              │                         ↑
              └─ 页面适配层 ─ 动画事务 ──┘ 完成时仅提交一次
                    │           │
             当前/目标快照    渐变策略 / 原版 iOS 算法与渲染器
                    ↑
           一个可复用的预览 WebView
```

**首选验证一个独立预览 WebView。** 它复用相同 EPUB、本地 URL、字号字体、CSS、视口和 foliate-js，由当前页首 CFI 定位，再用原 `next/prev` 得到目标页。主 WebView 在拖动和取消过程中不移动；预览实例的事件只回页面提供器，不能连接进度、同步、目录 UI 或朗读。最多保留一个预览实例，按需创建、串行准备，不能为每张缓存页创建实例。

相较于在主 WebView 中“先翻目标页截图、取消再跳回”，该方案避免临时改变主 `view.lastLocation`、导航历史和 TTS 可见范围。代价是额外 WebView/章节排版与内存，应在验证阶段决定能否接受。预览实例必须复用受控资源加载与 URI 授权，不能扩大文件访问权限。

捕获技术需要实机选择：先验证受控布局的预览 View 在当前页遮挡下，等待 `postVisualStateCallback` 后捕获页面；核对 `WebView.draw(Canvas(bitmap))` 对字体、图片、SVG 的实际输出。不能假定 `GONE`、零尺寸或透明离屏 WebView 仍会正常合成；PixelCopy 从窗口复制也不等于能复制被遮挡的 View。如捕获不可靠或开销过高，暂停该路线并提交差异方案，不能擅自切换为主页面预翻回滚或重写分页。

预览加载完成需综合：布局版本匹配、字体就绪、可见图片完成/失败、页首位置已确定及视觉提交；单次 `requestAnimationFrame` 不代表资源全部就绪。准备有超时与可取消请求，失败不缓存半成品。快照不包含工具栏和原生设置面板，包含阅读主题背景；新页面准备阶段复用相同背景设置。

### 5.2 翻页事务与位置提交

每次事务固定 `bookSession + layoutRevision + originCfi + direction + requestId`；页面身份还包含章节和页首定位信息，不能只按 fraction 缓存。快照 key 增加尺寸、排版/主题/图片版本；朗读高亮等动态绘制另有版本，避免旧图重复使用。

```text
Idle → Preparing → Dragging / 自动动画 → Settling
                                    ├─ 取消 → Idle，主页面不移动
                                    └─ 完成 → Committing → 主页面视觉就绪 → Idle
```

1. 准备当前与目标快照。未就绪时维持当前正文，不先空白翻卷；首页/末页在预览实例中根据实际页边界与位置变化判定，不能把 JS 的 `return true` 当作翻页成功。
2. 拖动只更新动画姿态；iOS 用原 CurlPan 判定完成/取消，渐变用原 0.1 阈值。动作取消、版本失效和新导航必须终止旧异步回调。
3. 仅当手势判定完成或点击动画到端点，才在主 WebView 执行一次原有阅读链路的 `next/prev`，关闭这次 foliate slide。提交期间缓冲该事务的 `relocate`，保留终帧覆盖层。
4. 等主页面实际落点及视觉提交就绪，再发布一次真实页首 CFI，沿用既有 `updatePosition`、保存和同步。比对目标不能只做 CFI 字符串相等，要验证同一章节及目标页可见范围/页首语义。
5. 提交失败或目标不一致时，停止动画，受控恢复原 CFI 并确认视觉就绪后解除覆盖层；事务内的失败落点不发布。恢复也失败时显示现有阅读错误状态并允许重新加载，禁止把猜测的目标页记为成功。

初版沿用上游程序翻页运行时不接受重复请求的策略：正在收尾/提交时合并或忽略重复点击，不堆积无界动作队列；手势正在进行时不启动第二事务。验收要求快速连续输入后状态正确、可继续翻页；若要保留每一次输入，需要另行确认与上游手感的差异。

### 5.3 手势与外部导航

新增模式才启用动画手势仲裁；现有 slide/none 保持原路径。横滑被动画识别后，必须取消 WebView 原触摸序列，并防止 JS touchend 再调用 snap；仅关闭 `animated` 属性不足以关闭 JS 横滑。优先由原生父容器正确拦截，必要时在 JS 增加最小手势开关，避免同时识别两次。

长按选择、选区拖动、链接、缩放、系统返回边缘手势和左侧亮度优先按现有行为处理；选择/缩放过程中不启动翻页。iOS 的识别参数沿用 CurlPan，渐变沿用通用方向捕获和原阈值；像素/density/CSS 像素的换算统一在适配边界完成。

TTS 的 `SpeechHighlight.set/render(true)` 能直接导航，必须纳入导航冲突处理。阅读目录、进度跳转、远端进度应用、TTS 定位发生时，取消未提交动画并使快照失效，再执行原导航；已开始提交的动作先按串行顺序收敛。为保持现有朗读时间与范围规则，初期 TTS 跟随继续走原定位方式，不强行为跨句定位添加卷曲动画；其跨页/跨章和高亮必须通过回归验收。

### 5.4 设置与异常处理

保留 `none`、`slide` 字符串及已有 DataStore key，新增 `ios_curl`、`fade`。默认仍为原来的 `slide`，已有用户值不迁移为新模式。设置显示“无 / 滑动 / iOS 仿真 / 渐变”，沿用 Material 3 控件并处理窄屏换行。

纯动画切换只更新控制器和动画标志，不重新应用字体、边距或触发章节重排；现有 `applySettings` 每次调用会应用整套样式，需要按字段差异处理。切换前取消未提交事务，保持已提交 CFI。上下滚动仍使用原方式，新增动画偏好保留，回到左右分页后恢复；不把 iOS 卷曲强行应用到连续滚动。

| 异常 | 建议行为 |
| --- | --- |
| 目标未准备、章节加载失败 | 保持当前页，提示现有加载错误；确认可翻时可走一次旧方式，不能两条路径重复翻 |
| 中断、ACTION_CANCEL、多指进入 | 取消未提交事务，主阅读进度不变 |
| 动画中改字号、背景、方向、尺寸 | 取消或收敛事务，按已提交位置应用设置，清理过期缓存 |
| 后台、退出、换书 | 失效 session，取消捕获/动画/提交回调；按既有退出逻辑保存最后已提交位置，释放预览与渲染器 |
| Mesh/GLES 失败或内存不足 | 保留当前快照至主正文可见，单次降级旧方式；不反复分配和重试，不改用户保存偏好 |

## 7 性能与兼容性风险

| 风险 | 约束与验证重点 |
| --- | --- |
| 预览 WebView 的额外排版和内存 | 仅一个实例；只预热有限相邻页；章节解析不能进入动画帧循环；先测低内存设备再决定保留策略 |
| 捕获卡主线程、图片/字体后到 | View 操作无法全部移出主线程；只在准备时捕获，控制次数与取消；测首次翻页延迟，资源变更使缓存失效 |
| 两个实例分页结果不同 | 同尺寸/CSS/字体/缩放，等待布局稳定；提交验证实际落页；fixed-layout EPUB 单独覆盖，不能假定与流式 EPUB 等价 |
| GPU/Java 双重内存 | 位图池最多 current/previous/next 三张并加字节上限；考虑上传纹理、输出位图、缓冲及双 WebView 额外占用 |
| 渲染降级卡顿 | 保留原 API 34+ Mesh 与 GLES 窗口输出；测 GPU 驱动和 API 26–33；禁止把逐帧读回作为默认快路径 |
| 主线程网格计算与临时对象 | 保留上游复用缓冲；用 trace 判断热点后局部优化，不预先改采样精度与阴影算法 |
| 快速动作导致错页/闪回 | 单事务、请求版本、终帧保留；捕获/提交回调与 View 生命周期同时检查有效性 |
| 朗读高亮与缓存冲突 | 高亮有独立版本；外部跟随导航取消动画，必要时使本次动画降级，不能延迟真实朗读定位 |
| 自定义背景 | 静读当前主题/图片能力按实际设置传递；完整捕获背景，透明背景不强走 Mesh 快路径；不顺带新建主题系统 |

内存估算：1080×2400 ARGB_8888 单张约 **9.9 MiB**，三张约 **29.7 MiB**；两张 GPU 纹理再约 **19.8 MiB**，尚未计 WebView、输出和窗口缓冲。缓存数量限制不能替代进程 PSS、native/GPU 监测；低内存设备允许减少预热、释放预览或回退旧方式，不能无条件保证三页常驻。

## 8 分阶段实施与验收

| 阶段 | 工作与退出条件 |
| --- | --- |
| 阶段 0 本次 | 提交源码调研、方案、复用范围和许可风险；不接入产品功能 |
| 阶段 0 补充验证，经本方案确认后 | 最小验证预览 WebView 的双向/跨章定位、稳定捕获、取消不产生进度事件；对比主/预览字体图片；测捕获时间和 PSS。许可路线同时确认。任一关键项失败先回报方案差异 |
| A 基础与渐变 | 建立快照与提交协议，移植渐变公式、阈值、曲线；完成双向、取消、错误与重复输入；对照旧模式和进度事件数量 |
| B iOS 仿真 | 移植全部算法及两种渲染路径，接入原控制器；先用固定两页图片比对网格、阴影、起卷和收尾，再连接 EPUB |
| C 设置与整体验收 | 正式开放选择和持久化，完成主题、TTS、同步、选择、旋转和生命周期回归，清理临时入口与依赖 |

功能与测试按下列口径验收：

- **算法与视觉**：条件允许时移植原 `IosCurlTurnTest`、`CurlMeshCompatibilityTest`、`ShadowProfileTest`、`IosCurlGraphicsLifecycleTest` 及 `IosCurlRendererDeviceTest`，保留原测试向量；另以可控帧时间验证默认 360 ms、渐变 0.1 阈值、两方向及取消。上游测试存在不代表静读已通过。
- **页面与位置**：流式 EPUB 含长章、极短章、图片/字体、非线性 spine 项；补 fixed-layout、横竖屏及可用的 RTL 书样。首页/末页不改变位置；跨章只提交实际目标页；取消后 CFI、章节、fraction、数据库及待同步位置均不变化；提交只有一个最终事件。
- **交互与故障**：连续点击/反向拖动、ACTION_CANCEL、多指、选区拖动、链接、亮度、工具栏、目录跳转；慢图、坏章节、捕获失败、低内存、后台和换书。失败后能继续阅读，无重复翻页、黑白屏或过期回调提交。
- **TTS 与同步**：朗读中手动翻页、跨页高亮、跨章续读与结束；翻页/取消前后核对 KOReader 同步位置，目录和远端跳转不触发陈旧动画。重启恢复偏好和原阅读位置，切换动画不改位置。
- **视觉对照**：使用本 ZIP 构建的参考版本、同一本 EPUB、同设备和相近排版，记录点击及拖动轨迹，比较起卷/中段/收尾、纸背/阴影、渐变方向与节奏；正文布局差异单独说明，不能据此忽略动画差异。
- **性能**：API 26–33 的 GLES 设备、API 34+ 的 Mesh 设备及至少一台低内存设备；记录冷/热准备延迟、帧时间、掉帧、Java/native/PSS。60 Hz 下 16.7 ms 为帧预算目标，报告 P95/P99 和超预算比例，并与旧模式对照。建议 30 分钟、至少 1000 次翻页，间隔采样内存并多次退出重进，检查是否持续增长。

开发时先运行相关 JVM/JS/仪器测试，再执行现有回归与测试变体构建：`node --test tests/*.test.mjs`、`:reader:testDebugUnitTest`、`:app:testTtsTestDebugUnitTest`、`:app:assembleTtsTestDebug`，仪器测试任务按最终放置模块执行。当前阶段只有文档变更，不以构建成功替代动画验收，也未运行设备性能测试。
